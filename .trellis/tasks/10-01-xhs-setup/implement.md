# 实施顺序

先做电脑侧，再用主机测试把设备状态机定下来，最后才接 ESP-IDF 的热点和 HTTP。每一步都能单独停住。

## Checklist

1. 为配对状态、控制台登录状态和「响应不含密钥」写 Python 测试。登录浏览器使用假实现。
2. 在现有后端上增加本机控制台、Cookie 数据卷读写、配对确认和设备轮询。统计与头像路径保持原样。
3. 增加 Dockerfile、Compose，以及 Windows 启动脚本。脚本启动宿主机发现进程，再执行 Compose。设备 API 用 `8787`，控制台只用 `127.0.0.1:8790`。
4. 把配网状态机放进与 ESP-IDF 无关的逻辑，并扩 `tests/test_xhs_logic.c`：成功后才保存、失败保留旧配置、确认后才接受令牌、重新配网保留统计数据。
5. 扩展 `xhs_store` 的 NVS 字段。把 `main/xhs_config.h` 换成空模板，不要把当前已填写的密码或令牌提交进去。
6. 实现短时 APSTA、有界配网页、广播和直连轮询。成功后关闭热点、DNS 和配网 HTTP。新增中文先核对现有字库覆盖。
7. 设置页增加「重新配网」。按键回调只发事件，连接和存储放在已有的工作任务里。

## Validation

迭代时跑与改动对应的主机测试。交付前跑：

```bash
./tools/validate.sh --static
```

固件有 ESP-IDF 5.5.3 时再跑 `./tools/validate.sh --firmware`。不要把编译成功写成板级通过。板级至少留这些未在主机上证明的项：手机打开热点页、错误密码、广播后控制台出现配对码、确认后仪表盘能取到数据、重新配网。

## Risky files

- `main/xhs_config.h`：工作区里已有真实密码和令牌。改成空模板时不要把原内容写进日志、文档或提交。
- `main/xhs_net.c`：这里从纯站点改为短时 APSTA。失败路径必须停掉新开的 netif、HTTP 和事件处理。
- `main/xhs_store.c`：NVS 初始化失败时禁止擦除分区。
- `backend/xhs_server.py`：新增页面不能把 Cookie 或令牌写进响应。

## Rollback points

- 第 3 步之后，电脑侧可以用现有固件加手工地址做接口检查。
- 第 4 步之后，状态机测试不依赖设备。
- 第 6 步若热点把内存耗尽，停在主机测试已通过的状态，不把 AP 留在常开模式。
