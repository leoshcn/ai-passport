# 熄屏待机设计

## Boundaries

| 层 | 职责 |
| --- | --- |
| `xhs_logic` | 在 `xhs_app_t` 上记录 `standby`。仪表盘的确定单击置位并清除本事件的拉取、保存和重新配网请求。已待机时，上/下单击、确定单击、确定长按只清标志。不访问背光、LVGL 或网络。 |
| `main.c` | 处理完事件后按 `standby` 把背光设为 0 或 70%。待机时跳过「降到 8%」。按键回调仍只入队。 |
| BSP | 继续提供单击、长按和 `bsp_display_backlight()`。不新增显示睡眠接口。 |
| `xhs_net` / `xhs_store` | 不改。待机时拉取结果照常入库，并刷新已经建好的界面对象。 |

## Flow

未待机、画面是仪表盘、事件是确定单击：`standby = true`，`request_fetch = false`。其他画面和其他按键沿用 `xhs_app_handle()` 现有分支。

已待机：上单击、下单击、确定单击、确定长按都只把 `standby` 清掉并返回。必须写在仪表盘确定单击分支之前，否则点亮用的那一次确定会马上再次熄屏。

拉取成功或失败不读、不写 `standby`。配网阶段变化也不清待机。

`main.c` 在逻辑返回后设置背光，不能先把已变暗的背光抬到 70% 再处理事件：

- 处理后 `standby` 为真：背光 0。空闲计时视为已经处理过，避免 30 秒逻辑再写成 8%。
- 这一次事件退出了待机，或事件前背光是 8% 且这次没有进入待机：背光 70%，空闲计时重新开始。
- 其余情况不改背光。

`BSP_BTN_PRESS` 和 `BSP_BTN_DOUBLE` 继续不映射。按下瞬间若提前点亮，随后到达的单击会在仪表盘上再次进入待机。

## Trade-offs

芯片睡眠省电更多，但这块板没有按键唤醒电路，功能键又靠 ADC 采样。睡眠后无法用单击点亮，所以待机只关背光。面板在强光下可能仍能看见残影。可恢复的 DISPOFF 留到真机确认背光 0 不够黑时再加。本任务不拆 SPI、不发 Sleep In。

30 秒降到 8% 与单击熄屏是两档。8% 时按键仍执行原动作，所以仪表盘上这一下确定的结果是背光 0。全灭之后的第一下只点亮。

立即刷新留在设置项里。仪表盘确定单击不再请求拉取。

## Rollback

待机标志和背光分支可以整段撤回。撤回后仪表盘确定单击要恢复为已配网时的拉取请求，30 秒变暗保持。不要把撤回和 `bsp_display_prepare_deep_sleep()` 的引脚改动混在同一次修改里。
