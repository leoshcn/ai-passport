# 小红书仪表盘后端

这个服务跑在和 AI Passport 同一个局域网里的电脑上。设备用明文 HTTP 来取数，服务再用操作者自己已经登录的创作平台会话去读数据。

它不会代填密码、不会破解验证，也不会伪造平台签名。Cookie 只能来自你有权使用的创作者账号。不要提交 Cookie、设备令牌或 Wi-Fi 密码。

## 在 Windows 上运行

在仓库根目录执行：

```text
powershell -File backend/start-xhs.ps1
```

这条命令会启动宿主机上的发现进程，然后执行 `docker compose up`。

- 设备 API：`0.0.0.0:8787`。配对完成后设备走这个端口。
- 操作控制台：只在 `127.0.0.1:8790`。局域网里的其他机器打不开。
- 发现进程在物理局域网上接收设备的 UDP 广播，再把回复单播回去。回复里的地址是和设备匹配的那块网卡的 IPv4，不会是 `172.x`、WSL 网卡或 `host.docker.internal`。

请在 Windows 防火墙里放行 `com.docker.backend.exe` 的入站 TCP `8787`，以及发现进程的入站 UDP `8788`。如果 Docker Desktop 被设成只把端口绑在本机，设备就连不上 `8787`；Compose 文件把设备 API 固定发布在 `0.0.0.0`。

浏览器打开 `http://127.0.0.1:8790`。页面只有三种状态：未登录、已登录、已失效（`logged_out`、`logged_in`、`expired`）。登录会用程序控制的浏览器打开创作者平台自己的扫码页。只有现有的统计拉取成功之后，Cookie 才会写入数据卷。粘贴 Cookie 走同一条检查。页面、日志和设备的统计响应都不包含 Cookie 或设备令牌。

退出登录会清掉已保存的创作者会话和统计缓存，以便换一个账号再扫码。设备配对和令牌保留。设备屏幕会继续显示上一份数字，直到新账号的数据拉取成功。

Cookie 和配对状态放在 `xhs-data` 数据卷里，容器重启后还在。

`GET /api/v1/stats` 和 `GET /api/v1/avatar` 保持原样。两个请求都要带 `X-Device-Token`。统计缓存 30 秒。缺少 Cookie 或会话被拒绝时返回 HTTP 503 和 `{"ok": false}`，日志里不写 Cookie。

近 7 日净涨粉会在创作平台同时给出掉粉数时用新增减去掉粉。如果响应里只有 `rise_fans_count`，就使用这个 7 日新增粉丝数。

## 设备配网

`main/xhs_config.h` 是空模板。不要把 Wi-Fi 密码、后端地址或设备令牌写进去。没有已保存的配网记录时，设备打开开放热点 `Passport-Setup`，配网页在 `http://192.168.4.1`。页面收集家里的 Wi-Fi 名称、密码，以及可留空的后端地址，例如 `http://<这台电脑的局域网 IP>:8787`。

设备只有在站点拿到 IP 之后才把 Wi-Fi 写入 NVS，然后关闭热点、DNS 和配网 HTTP。错误密码不会被保存。如果已经有一份可用记录，这次失败会保留它。

后端地址留空时，设备广播 4 位配对码并显示在屏幕上。填了地址就改为向该后端轮询，不再广播。两种情况都要在控制台确认一次。后端然后生成一个设备令牌，只交给这台设备。之后再确认会替换原来的令牌。

设备设置里的「重新配网」会清除 Wi-Fi、后端地址和令牌，保留 `xhsdash` 命名空间里的上次统计，并重新打开热点。NVS 初始化失败时不会擦除分区，屏幕显示：配置失败，请重新刷新固件。

## 设备按键

- 仪表盘上短按确定：立即向后端要一次数据。
- 长按确定：进入设置。
- 设置里用上、下键切换「自动更新」「更新频率」和「重新配网」。确定后进入调整；自动更新和更新频率用上、下键改值，再按确定写回。
- 「重新配网」需要再按一次确定。确认后清除 Wi-Fi、后端地址和令牌，保留上次统计，并回到热点。
- 在设置里长按确定：保存并回到当前主画面。

自动更新默认打开，周期默认每天一次。屏幕空闲约 30 秒后背光降到 8%。右上角是电量；电量计没有读数时留空。
